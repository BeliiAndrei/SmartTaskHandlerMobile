# SmartTaskHandlerMobile
PAM Labs
SmartTaskHandler — мобильное приложение для управления логистическими задачами
Домен: складская логистика / управление задачами

L5 backend: .NET 9 Minimal API в `server/`; запуск: `cd server && dotnet run`.
Печатный QR и готовая локальная демонстрационная задача: [demo/README.md](demo/README.md).

## Lab 5: .NET backend и Flutter

В выданном комплекте нет `openapi.yaml` и `conformance/`, поэтому официальный
набор проверок курса запустить нельзя. После запуска сервера базовые и новые
маршруты проверяются командой `pwsh -NoProfile -File server/tests/smoke.ps1`
из корня проекта (23 проверки). Отдельный живой тест Flutter ↔ .NET:
`flutter test test/auth_backend_integration_test.dart test/task_backend_integration_test.dart --dart-define=RUN_LIVE_BACKEND=true`.

Формы входа и регистрации теперь обращаются к серверу. JWT хранится в
`shared_preferences`, пароль локально не сохраняется. При запуске наличие JWT
выбирает начальный экран; серверный 401 при проверке сохранённой сессии удаляет
JWT и возвращает на вход. Выход также удаляет JWT. Список задач подключён через
`HttpWarehouseTaskRepository` в корне композиции. Тестовый mock
перенесён в `test/support/`, в рабочей сборке он не используется.
Роль и данные профиля читаются из защищённого `/profile`; при недоступности сервера
временно используется роль обычного пользователя. Любой 401 на запросе задач
удаляет JWT и переводит на экран входа.

Список задач получает страницы по 20 записей с сервера; поиск отправляет
`search` на backend, следующая страница загружается при прокрутке. Формы берут
точки отправления и назначения из `GET /locations`. Карточка перечитывает
`GET /tasks/{id}` и показывает историю статусов из `GET /tasks/{id}/history`.
Создание идёт через `POST /tasks`, редактирование и удаление — через
`PUT /tasks/{id}` и `DELETE /tasks/{id}`;
статус меняется через PATCH. Для завершения необходимо отсканировать QR-код
конечной точки: приложение сравнивает его с каталогом, затем посылает
`POST /tasks/{id}/qr-confirmation`. Сервер повторно проверяет совпадение.

Фото во вкладке «Неликвид» остаются локальными; тема L5 — складские задачи
с QR-подтверждением и не требует вложений в задачу. Загрузка в `/files` здесь
не нужна по условию задания 7.

При остановленном сервере список показывает ошибку и кнопку «Повторить», без
offline-кэша задач (он предусмотрен для L6).

По умолчанию Android-эмулятор обращается к `http://10.0.2.2:8080`, desktop/web —
к `http://localhost:8080`. Для физического телефона укажите IP компьютера в
одной сети: `flutter run --dart-define=API_BASE_URL=http://192.168.1.10:8080`.

Описание: SmartTaskHandler — мобильное приложение для сотрудников склада: список назначенных задач, их описание, приоритет и история выполнения. Решает проблему передачи заданий устно или на бумаге: сотрудник получает актуальную задачу в телефоне и отмечает ход её выполнения. Целевая аудитория: сотрудники склада и небольших логистических подразделений.

Обязательные экраны (6–8):
- Вход / регистрация
- Список задач с поиском и фильтром по статусу
- Карточка задачи: название, описание, приоритет, срок и статус
- Форма создания / редактирования задачи
- Экран изменения статуса задачи
- История выполненных задач
- Профиль пользователя

L2: статические экраны списка задач, карточки задачи, формы создания, истории и профиля с «зашитыми» данными; Material 3.

L3: навигация список задач → карточка → изменение статуса; список задач → форма создания/редактирования; валидация формы задачи: обязательное название, описание и срок выполнения.

L4: состояние списка задач: создание, редактирование, удаление и изменение статуса; Repository с mock-задачами и пользователями.

L5: интеграция с backend: GET /tasks, GET /tasks/{id}, POST /tasks, PUT /tasks/{id}, DELETE /tasks/{id}, PATCH /tasks/{id}/status; JWT-аутентификация. Добавить сканирование QR-кода для подтверждения выполнения задачи. QR-код содержит идентификатор точки назначения; приложение проверяет, что отсканированная точка соответствует задаче.

L6: offline-кэш списка задач, тесты основных сценариев и release-сборка.

## Структура интерфейса Lab 2

Исходники разделены по назначению:

- `lib/screens/` — отдельный файл для каждого экрана приложения;
- `lib/widgets/` — переиспользуемые компоненты интерфейса;
- `lib/models/` — модель складской задачи и перечисления;
- `lib/data/` — общие mock-данные для списка, истории и профиля.

`TaskCard` переиспользуется на экранах списка и истории. `LabeledValueRow`
переиспользуется на экранах деталей задачи и профиля. Оба компонента получают
данные через параметры конструктора, поэтому их внешний вид меняется в одном
месте для всех экранов.

## Лабораторная №3: маршруты и локальные формы

Приложение стартует на `/login` через `MaterialApp.router`. Карта маршрутов
находится в `lib/router.dart`; разделы `/tasks`, `/favorites`, `/unsellable`, `/history`, `/profile` образуют
пять ветвей `StatefulShellRoute.indexedStack` с постоянным `NavigationBar`.
`/login` и `/register` расположены вне shell. Вложенные адреса:

- `/tasks/new` — форма создания;
- `/tasks/:id`, `/favorites/:id` и `/history/:id` — детали, которые ищут задачу по `id` в mock;
- `/tasks/:id/edit`, `/favorites/:id/edit`, `/history/:id/edit` — форма редактирования;
- `/tasks/:id/status`, `/favorites/:id/status`, `/history/:id/status` — выбор статуса.

Для открытия деталей и форм используется `context.push`, для завершения формы —
`context.pop`, после входа и подтверждённого выхода — `context.go`. Форма
проверяет обязательные название, описание, зону и срок. E-mail должен содержать
`@` и доменную точку, пароль — не менее шести символов; регистрация дополнительно
проверяет совпадение паролей. Успешные действия дают `SnackBar`, выход запрашивает
подтверждение через `AlertDialog`.

В L3 задачи остаются mock: успешное заполнение формы и выбор статуса не меняют
список. Избранное сохраняется локально; остальные изменения задач предусмотрены в L4.

Проверка: `flutter analyze`, `flutter test`, `flutter run`. Виджетный тест
`test/lab3_flow_test.dart` проходит вход, адресную навигацию, валидацию,
переключение вкладок с сохранением поиска и подтверждение выхода.

## Локальное избранное

Звёздочка в списке, истории и деталях добавляет задачу в избранное или удаляет
её. Вкладка `/favorites` показывает задачи, чьи ID есть в хранилище. После
перезапуска приложения выбор сохраняется.

`FavoriteRepository` записывает JSON `favorite_task_ids.json` в служебную папку
приложения (`getApplicationSupportDirectory` из `path_provider`). Формат:

```json
{
  "taskIds": [1042, 1043]
}
```

Сохраняются только ID; названия и остальные поля по-прежнему читаются из
`mockTasks`. Файл создаётся при первом изменении избранного. При ошибке чтения
приложение не перезаписывает повреждённый JSON; вкладка предлагает повторить
загрузку.

Проверка: `flutter test test/favorites_test.dart` покрывает сохранение и повторную
загрузку JSON, неверный файл и интерфейсный поток добавления и удаления.


## Неликвидный товар с фотографией

Во вкладке «Неликвид» (`/unsellable`) можно открыть форму добавления товара.
Название, причина и фотография обязательны. Фото можно сделать камерой телефона
или выбрать из галереи; выбранный снимок показывается в форме до сохранения.
После сохранения товар появляется в списке и открывается в отдельной карточке.

`image_picker` возвращает путь к выбранному изображению. При сохранении приложение
копирует файл в служебную папку `unsellable_photos`, а сведения о товаре и имя
файла записывает в `unsellable_reports.json` в `getApplicationSupportDirectory`.
Фотографии и записи остаются на устройстве после перезапуска приложения.
Данные локальные: синхронизации с сервером и другими устройствами пока нет.

Проверка кода: `flutter analyze`, `flutter test`, `flutter build apk --debug`.
На телефоне дополнительно проверить оба источника фото, создание записи,
открытие карточки и сохранение после перезапуска приложения.
